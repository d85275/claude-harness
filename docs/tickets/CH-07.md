## Scope

Places where the guard (`guard.py`, `bash_rules.py`; `other_build_running` and `check()` now live in `bash_rules.py` after CH-08) turns "couldn't tell" into "all fine" without telling anyone:

- `load_input`: unreadable hook stdin becomes `{}`, so every guard allows silently. Report it through the CH-01 warning channel.
- `other_build_running`: if `pgrep` is missing or times out, the result is "nothing running", so a machine-wide simulator reset isn't blocked. Report it, and treat "can't tell" as ask for that rule.
- `notify`: an osascript failure and its return code are ignored. Report once.
- Duplicate keys in `harness.json` are silently resolved to the last one. Report them (`object_pairs_hook`).
- A crash inside `guard_read`/`guard_bash` is reported (CH-01) but still allows the call. **Owner decision 2026-11-23:** when the call looks like it touches a credential path, emit `ask` instead; any other crash keeps allow plus the warning.
- Cost of the credential check on huge commands (found in the CH-03 review; it predates CH-03): `shlex.split` over a 1 MB single word takes about 22 s of CPU, and a 1 MB `python3 -` heredoc about 6 s. Both are past the 10 s hook timeout, and a timed-out hook does not block. Put a size check before the credential pass: past the cap, ask as "too large to check".
- Failed import at hook start (found in CH-08; it predates the split): if `harness_config`, `bash_rules`, `shell_check` or `shell_scan` can't be imported, the hook exits 1, which Claude Code treats as allow. Guard the imports: on failure, emit `ask` for Bash, Read and Edit with "dev-harness guard could not load: <error>", never allow silently.
- Tighten the no-I/O tests for `shell_scan.py` and `shell_check.py` (CH-08 review): allow only `os.path.*`, `os.getcwd` and `os.sep` from `os`, and ban `__import__`.
- The config warning currently fires on every tool call. De-duplicate it, e.g. by validating once from a SessionStart hook or with a marker keyed by the config file's mtime.

Don't: change allow/ask/block decisions beyond the `pgrep` case and the crash option. The subagent push item moved out: the owner chose a feature-branch push rule for every session instead (CH-09).

## Findings

- The credential pass (`shlex.split` in `bash_rules.check`) is inside the allowed files. Under `shell_scan.LONGEST_COMMAND` (262144) it uses shlex; past it, plain whitespace words. Tokens are de-duplicated and checked against a 4 s deadline (`CREDENTIAL_SECONDS`). A credential hit blocks as before at any size; only "no hit" past the cap, or the deadline running out, asks "too large to check". It sits after the device-reset rules, so a reset still blocks.
- The config warning is de-duplicated with a marker file (temp folder, keyed by problems, config mtime and size, session id), not a SessionStart hook; `hooks/hooks.json` is unchanged. The marker is written by `emit()` only after output carrying the warning was printed, so a block or a notify call does not consume it; notify has its own key. No usable session id, or an untrusted or unwritable marker folder (file, symlink, other owner), means the warning shows on every call. stderr always gets it.
- `test_nested_rules_still_apply_when_the_root_is_malformed` ran two calls on one config state and expected the warning twice; its second call now uses a fresh `TMPDIR`.
- Crash handling: `looks_credential` (whole body guarded) uses a text pattern plus the configured globs through shlex, and answers yes when it cannot tell (odd input, config not loaded, too large, too slow). The crash handler has a last-resort try. The crash tests use a read-verb command with `cwd=5` (a bash command like `ls` fails closed in `check()` before reaching the crash handler).
- Review round 1 (4 Important, 6 Minor) is fixed in the amended commit. Mutation 7b (removing the `CFG is None` check) is not caught: the old path then raises inside the guarded body and also answers yes, so behaviour is the same.
