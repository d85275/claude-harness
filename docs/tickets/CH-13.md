# CH-13: Stash and `core.hooksPath` checks fail closed; load-tolerant timing tests

## Status

done (2026-11-23), integrated as 9283d96 after two review rounds (round 2 fix verified by the coordinator)

## Depends on

CH-12 (shared `data_text_unsafe`)

## Scope

Two follow-ups from the CH-12 review.

1. **Stash and `core.hooksPath` (CH-04):** `git_state_hits` in `bash_rules.py` reads `shell.texts` and skips hits inside data-heredoc spans even when a `DATA_TEXT_UNSAFE` check holds. Example: `echo hi # c` on one line, then `cat > t.txt <<'EOF'` with `git config core.hooksPath /x` in the body: no ask, while `cat() { bash; }` would run it. Drop the spans for those text entries when `data_text_unsafe` holds, using CH-12's helper.
2. **Timing tests under load:** the full suite failed 1–2 tests twice, only while the machine was very busy (load average 150–430), and passed on rerun. Likely tests with real deadlines or wall-clock asserts:
   - `shell_scan.CHECK_SECONDS` (1.5 s) and `bash_rules.CREDENTIAL_SECONDS` (4 s) in tests that aren't about the deadline;
   - `tests/test_data_heredoc_rules.py` `test_big_body_under_the_cap_is_exempt`;
   - `tests/test_fail_open.py`: `test_hit_before_the_deadline_still_blocks_in_a_big_command`, `test_repeated_tokens_are_checked_once`, `test_huge_command_is_fast`, the many-distinct-tokens test.

   In tests that aren't about the deadline, patch the deadline high (e.g. 60 s). Where a time assert is the point, use `time.process_time()` (as `tests/test_guard.py` does) or a generous limit. Don't weaken what any test proves.

### Must catch (ask, with two or more worktrees for stash)

- each `DATA_TEXT_UNSAFE` trick combined with `git config core.hooksPath x` in a data heredoc body
- the same with `git stash` in a multi-worktree repo
- CRLF cases as unit tests (the corpus loader can't hold `\r`)
