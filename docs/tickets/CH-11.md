# CH-11: Protect SSH private keys and read paths inside `$(…)`

## Status

in progress (2026-11-23); owner: test files may be written with the file tools

## Depends on

CH-10 (both touch the credential pass in `bash_rules.py`)

## Scope

Two gaps found while building CH-10. Both exist on `main` before CH-10:

1. **SSH private keys are not protected by default.** `cat ~/.ssh/id_rsa` is allowed, because the default protected paths have no SSH key names.
2. **A path glued to shell punctuation is missed.** In an unquoted context, `$(cat .env)` gives the token `.env)`, which no protected glob matches.

This ticket only adds protection.

### Must catch (block, like other credential reads)

- `cat ~/.ssh/id_rsa`, `id_ecdsa`, `id_ed25519`, `id_dsa`, and a `-sk` variant (`id_ed25519_sk`)
- the same names in any folder (`**/id_rsa`), e.g. `cp deploy/id_ed25519 /tmp/`
- `echo $(cat .env)`, `x=$(cat .env)`, `` echo `cat .env` ``, `(cat .env)`, `{ cat .env; }`
- the corpus gap rows CH-10 recorded for these two cases flip to block

### Must pass

- public keys: `cat ~/.ssh/id_rsa.pub`, `id_ed25519.pub`
- `ssh-keygen -t ed25519 -f ~/.ssh/id_ed25519` (creates a key, doesn't read it)
- `ls ~/.ssh`, `cat ~/.ssh/config`, `cat ~/.ssh/known_hosts`
- every existing corpus row keeps its expectation

### How

- Add the private-key names to `DEFAULT_PROTECTED_PATHS`, with `.pub` excluded.
- Strip leading and trailing shell punctuation from each token before matching: `(`, `)`, `{`, `}`, `;`, `` ` ``, `$(`. Don't change how the command is split.
- Keep CH-07's size cap, de-duplication and deadline, and CH-10's data-heredoc exemption.

## Done criteria

- Every Must catch / Must pass item is a row in `tests/data/guard_corpus.txt`.
- A mutation check shows the new block rows fail without each fix.
- README: the protected-path list and known gaps updated (remove the two gaps).
- Full suite passes. Review rounds: at most 2.
