# CH-21: Check against real projects (read-only) and dogfood acceptance

## Status

planned (2026-11-23), Milestone B

## Depends on

CH-14 to CH-20

## Scope

Prove the ticket system works on real data before the 1.0 plugin update.

- **Real projects, read-only:**
  - Run `/ticket-init --check` and `dev-harness-board --root <project> --out <scratch>/board.html` against the owner's two projects, using paths from the coordinator's brief and never written into tracked files.
  - Output goes only to the scratchpad. Nothing is copied into this repo: no names, ticket text or screenshots.
  - Fix the parser or the adopt report until both projects render without errors and every reported difference is real or explained.
  - Compare the counts with each project's current board.
- **Dogfood:** run `/ticket-init` (adopt mode) on this repo.
  - Its own tracker (CH-01 to CH-21) must give zero `--check` problems.
  - The board must build.
  - The hooks are installed only if the owner agrees (this repo's CLAUDE.md treats hooks as high-risk).
- **Record** in the ticket file: commands, counts, the differences found and how each was resolved, described in general terms (no private names or ticket IDs).

Don't: write anything in the two projects (no `--check` side effects, no hooks, no board file there); commit any output from them.

## Done criteria

- Both projects: zero parser errors. Every remaining difference is either a setting suggestion or a listed, explained mismatch.
- A hash or mtime listing of each project before and after shows no file changed.
- This repo: `dev-harness-board --check` exit 0; the board opens with no console errors.
- Any parser fix comes with a fixture test, using made-up data shaped like the case that failed.
- Full suite and static check pass. Review rounds: at most 2.
