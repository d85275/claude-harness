# CH-02: Model tiers and implementer routing by review level

## Status

in review (2026-11-22)

## Depends on

CH-01 (`highRiskReviewerModel` key)

## Scope

Owner decisions 2026-11-22. Model aliases only, never pinned versions:

| Agent | Model / effort |
|---|---|
| `implementer` | Sonnet / medium (unchanged) |
| `implementer-advanced` (new) | Opus / high |
| `reviewer`, `silent-failure-hunter` | Sonnet / high (unchanged) |
| `high-risk-reviewer` | Opus / high; Fable when `highRiskReviewerModel` is `"fable"` |

No Haiku tier.

- New `agents/implementer-advanced.md`: same rules as `implementer`, with extra care for high-risk areas.
- `/start-ticket` reads the ticket's Review level: `high-risk` -> `implementer-advanced`, otherwise `implementer`.
- `/review` passes a model override to `high-risk-reviewer` when `highRiskReviewerModel` is set.
- Upgrade rule: an implementer that finds its diff riskier than planned says so in its report. The coordinator then sets the ticket to `high-risk`, so review always goes to `high-risk-reviewer`. Whether to redo the implementation with `implementer-advanced` is the owner's call.
- `/plan` marks a ticket `high-risk` when unsure and gives a one-line reason.

## Done criteria

- A test reads every agent's frontmatter and pins the table above. It also fails if any `model:` is anything other than a bare alias (`sonnet`, `opus`, `fable`).
- README "The loop" and "Agents" sections and `templates/CLAUDE-harness-section.md` describe the tiers and the upgrade rule.
- Full test suite passes.
