# CH-06: Device and build-tool rules become opt-in presets

## Status

planned (2026-11-22)

## Depends on

CH-01

## Scope

The machine-wide device-reset blocks are always on today: `simctl shutdown/delete/erase all`, `adb emu kill`, `killall Simulator|qemu|xcodebuild` while another `xcodebuild`/`gradlew` runs. They only make sense for mobile projects, so they move into named presets in `harness.json`:

- `"apple-simulators"`: the simctl/killall rules, busy check on `xcodebuild`
- `"android-emulators"`: the adb/qemu rules, busy check on `gradlew`

Deploy and destructive cloud commands (Firebase, gcloud, terraform, kubectl) **stay default asks**. They are outward-facing, cost nothing when the tool isn't installed, and removing them would weaken the plugin's main promise.

Owner decision 2026-11-22: presets switch on automatically when the project has an `*.xcodeproj`/`*.xcworkspace` (`apple-simulators`) or a `gradlew` (`android-emulators`), and a project can switch one off explicitly (e.g. `"presets": {"apple-simulators": false}` or an equivalent documented form). Repos that relied on the always-on rules therefore keep them after a plugin update with no config change; nothing gets weaker silently. Detection must be cheap (no deep tree walk on every hook call) and failing to detect must never be silent. `/ticket-init` (Milestone B) writes the detected presets into `harness.json` explicitly.

## Done criteria

- Tests: auto-on when `*.xcodeproj` / `gradlew` exists; explicit off switch; device reset passes with no preset and no mobile project; blocks with the preset while a build is "running" (busy check stubbed); unknown preset name is reported (via CH-01 loader).
- `templates/harness.json` and README document both presets.
