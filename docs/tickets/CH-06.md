# CH-06: Device rules as presets, auto-on for mobile projects

## Status

in progress (2026-11-23)

## Depends on

CH-01, CH-08

## Scope

Today the machine-wide device-reset blocks are always on. They block `simctl shutdown/delete/erase all`, `adb emu kill` and `killall Simulator|qemu|xcodebuild` while another `xcodebuild`/`gradlew` runs. They only make sense for mobile projects, so they become two presets:

- `"apple-simulators"`: the simctl and killall rules, with a busy check on `xcodebuild`.
- `"android-emulators"`: the adb and qemu rules, with a busy check on `gradlew`.

### Owner decision 2026-11-22: auto-on

A preset switches on automatically when the project has the matching files:
- **`apple-simulators`:** an `*.xcodeproj` or `*.xcworkspace` in a project root or one folder below it (e.g. `ios/App.xcodeproj`).
- **`android-emulators`:** a `gradlew` in a project root or one folder below it (e.g. `android/gradlew`).

"Project root" means each root the CH-01 loader found (the `CLAUDE_PROJECT_DIR` or `.git` boundary), so worktrees work too.

A project can force presets explicitly in `harness.json`:
- **On:** `"presets": ["apple-simulators"]` (the existing key, validated by CH-01).
- **Off:** `"disabledPresets": ["android-emulators"]`, a new key. Validate it like `presets`: unknown names are reported.
- **Merging:** union for both lists, so a nested config can switch a preset on but never off for the root.
- **Precedence:** an explicit "on" beats an explicit "off" from a different file. Within one file, "off" wins.

Detection rules:
- **Cheap:** a directory listing of each root and its direct subfolders, never a deep walk, and only when a device-reset command is detected.
- **Fail toward protection:** if a listing fails (permissions, I/O), treat the preset as on and add a `systemMessage`.

Deploy and destructive cloud commands (Firebase, gcloud, terraform, kubectl) **stay default asks**.

### Must catch (preset on, a build "running")

- `xcrun simctl shutdown all`
- `xcrun simctl delete all`, `xcrun simctl erase all`
- `xcrun simctl --set <path> delete all`
- `adb emu kill`
- `killall Simulator`, `killall qemu-system-aarch64`, `killall xcodebuild`

### Must pass

- the same commands when no build is running (as today)
- the same commands with no mobile project and no explicit preset
- a preset switched off explicitly
- per-device commands (`simctl delete <UDID>`)

## Done criteria

Tests (busy check stubbed, temporary project folders):
- auto-on via root and one-level-down `*.xcodeproj` / `gradlew`;
- explicit on;
- explicit off;
- merge precedence;
- listing failure, which means on plus a warning;
- unknown preset name reported.

Also:
- `templates/harness.json` and README document both presets, auto-on and the off switch. The CHANGELOG note goes in Milestone C.
- Full suite passes.
- Review rounds: at most 2.
