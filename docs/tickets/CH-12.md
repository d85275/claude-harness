# CH-12: Push and protected-config detection fail closed on unsafe heredocs

## Status

planned (2026-11-23), owner: after CH-11, before CH-09

## Depends on

CH-10 (its fail-closed checks), CH-11 (both edit the guard)

## Scope

CH-03's rule lets a hit inside a proven data heredoc body count as text, for the push regexes and the protected-config redirect check (`ShellCheck.run` in `shell_check.py`). The CH-10 high-risk review showed that three tricks make the scanner and bash disagree about what is a body, so a real `git push` is read as text and allowed:

- CRLF line endings: bash ends the body at `EOF\r`, the scanner at a later `EOF`;
- a `#` inside a nested `${x:-"…"}` quote, which the scanner reads as a comment;
- a shadowed owner: a `cat()` / `tee` / `git` function or alias, `PATH=`, `hash`, `mkfifo`, or `exec N>` that turns a "data" heredoc into something that runs.

CH-10 added fail-closed checks for these (`DATA_TEXT_UNSAFE` in `bash_rules.py`), but only for the credential and device-reset rules. Apply the same checks in `ShellCheck.run`: when any holds, no span removes a hit, and every push and protected-config match counts.

### Must catch (push policy `ask` asks; `deny` blocks)

- each trick above combined with a `git push` line that bash would run after or around the heredoc
- the same with a protected-config redirect (e.g. `> .eslintrc.json`)

### Must pass

- every existing corpus row keeps its expectation, including CH-03's data-heredoc rows (`git commit -F - <<'EOF'` with "git push" in the message) and CH-10's rows

### How

- Move `DATA_TEXT_UNSAFE` (and the outside-text and opening-line helpers it needs) to one place both files import; `shell_check.py` is imported by `bash_rules.py`, so put it there or in `shell_scan.py`. One table, not two copies.
- `ShellCheck.run` drops all spans when any check holds. `DataText` keeps using the same table.

## Done criteria

- Every Must catch item is a corpus row (CRLF cases as a unit test, since the corpus loader can't hold `\r`).
- A mutation check: removing the checks from `ShellCheck.run` fails the new rows; `DataText` behaviour unchanged (CH-10 rows still pass).
- README: remove the claim that publishing is always caught via the full text where it no longer holds, or reword it to match.
- Full suite passes. Review rounds: at most 2.
