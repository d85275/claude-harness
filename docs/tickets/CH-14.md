## Scope

The base of the ticket system: read a project's tracker and ticket files into one model, and report where they disagree. Rendering is CH-15; live worktrees are CH-16.

- New command `bin/dev-harness-board` (standard library only), with the code in a new folder `board/` (e.g. `board/model.py`, `board/parse.py`). This ticket adds only `--check` and `--json` (prints the parsed model, for tests and debugging).
- **Inputs** come from `tickets` in the merged `harness.json`:
  - `trackerPath`, `dirs`, `featureGlobs`, `idPrefixes` (platform and kind per prefix), `twinPlatforms`, `archive`.
  - Paths are relative to the repo root (`--root <dir>`, default: the git top level of the current directory, else the current directory).
- **Tracker:** the first Markdown table whose header has `ID` and `State` columns.
  - The ID cell may be a link (`[CH-01](CH-01.md)`).
  - Other known columns: `Title`, `Review`, `Commit`, `Note`. Any other columns are kept as extra fields, in order.
  - With `archive: true`, rows in the archive tracker (path in settings, see below) are read too.
- **Ticket file:** `# <ID>: <title>`, then `## Status`; the first word or words of the status line give the state.
- **States:** `Planned`, `In progress`, `In review`, `Fixing`, `Owner check`, `Done`, `Blocked`, `Deferred`. Matching ignores case.
- **New settings (`tickets`), all optional, validated like the other keys:**
  - `stateAliases`: an object mapping a project's own state names to the standard ones (e.g. `{"Waiting": "Blocked"}`);
  - `archiveTracker` and `archiveDirs`: where archived rows and files live when `archive` is true;
  - `extraColumns`: extra tracker columns to show on cards (names as written in the header).
- **`--check`** prints one line per problem and exits 1 if there is any, 0 if none, and 2 on bad usage or unreadable config. Problems:
  - a row whose state differs from its file's Status line;
  - a row with no file, and a file with no row;
  - an unknown state, after aliases;
  - a duplicate ID;
  - a link to a missing file;
  - a twin pair (when `twinPlatforms` is on) where only one side exists.
- **Robust:** a malformed row or file is a problem line, never a crash; a missing tracker is one problem line.

Don't: write any file; run git (CH-16 does that); copy code or names from any private project (the design notes in `docs/STATUS.md` are the reference).

## Done criteria

- Unit tests with small fixture projects under `tests/fixtures/` (made-up tickets only):
  - each problem kind is found;
  - a clean project gives exit 0;
  - aliases, extra columns, archive, linked IDs and CRLF files are handled;
  - a malformed table gives a problem line, not a traceback.
- `harness_config` validates the new keys (bad types give warnings and defaults), with tests.
- Running `bin/dev-harness-board --check --root .` on this repo: exit 0.
- The full suite and `py_compile` pass (extend the static check to `board/*.py`). Review rounds: at most 2.
