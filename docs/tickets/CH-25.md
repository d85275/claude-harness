## Scope

Rewrite `README.md` so a newcomer understands the plugin, starting from `docs/README-draft.md`.

- README: what problem it solves and for whom; the plan -> implement -> review -> integrate loop with the Mermaid flow chart; a short worked example of one ticket; what the guards stop (summary table); the ticket board with the CH-24 screenshots and a link to the example board; install and a 5-minute quickstart; limits; links.

- `docs/configuration.md`: the full `harness.json` reference, every key with type, default and example (generated or checked against `harness_config.DEFAULTS` by a test so it cannot drift).
- Nothing in the current README is lost: every guarantee and known gap ends up in one of the three files.
- Remove `docs/README-draft.md` once merged.

Don't: promise anything the code doesn't do; mention private projects.

## Done criteria

- A coordinator-run check that every heading or gap from the old README is somewhere in the new files.
- Review includes a first-time-reader pass (the reviewer reads only the README and says what is unclear), not only accuracy.
- Links resolve (a test or a script). Review rounds: at most 2.
