# CH-03: Push policy ("nothing leaves your machine without your approval")

## Status

planned (2026-11-22)

## Depends on

CH-01

## Scope

`guard.py` always asks before `git push`, `gh pr create/merge`, `gh repo create/delete` and `gh release create`. This ticket makes that behaviour a setting, `pushPolicy`:

- `"ask"` (default): the owner approves each one.
- `"deny"`: blocked outright, with a message saying the owner pushes by hand.
- `"allow"`: no prompt from this hook. The user's own Claude Code permission rules still apply. Documented as meant for the owner's interactive sessions; agents still never push.

Owner decision 2026-11-22: `pushPolicy` covers only git/GitHub publishing. Deploys and destructive cloud commands (`firebase deploy`, `gcloud … deploy/delete`, `terraform apply/destroy`, `kubectl apply/delete`, `askCommands`) always ask, whatever the policy.

Don't: change the credential or weakening guards.

## Done criteria

- Tests for each policy against `git push`, `git -C dir push`, `git -c x=y push`, `gh pr create`, `gh pr merge`, plus a deploy command that still asks under `"allow"`.
- One test pins the default as `"ask"` when no config exists.
- README states "nothing leaves your machine without your approval" and documents the three values.
