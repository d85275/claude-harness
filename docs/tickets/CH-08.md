# CH-08: Split `guard.py` into scanner, Bash rules and hook entry

## Status

done (2026-11-22), integrated as 99aedc3 after one high-risk review round (accept with minor notes)

## Depends on

CH-03

## Scope

After CH-03, `hooks/scripts/guard.py` is about 730 lines doing five jobs:
- hook plumbing (input, `emit`/`ask`/`block`, crash handler);
- a shell scanner (words, operators, heredocs, quoting, `$'…'`, work budget);
- the Bash rules (push policy, config writes, deploys, device resets);
- the Read/Edit guards (credentials, protected configs, weakening);
- notifications.

The scanner can't be tested or reviewed apart from the rules. CH-04, CH-05 and CH-07 would add more Bash rules to the same file.

Move the code, with no behaviour change, into:

| File | Contents |
|---|---|
| `hooks/scripts/shell_scan.py` | the pure tokenizer and work budget; no policy, no config |
| `hooks/scripts/bash_rules.py` | every Bash rule: credential reads, push policy, config writes, always-ask commands, device resets |
| `hooks/scripts/guard.py` | entry point, emit/ask/block, crash handler, dispatch, Read/Edit/notify guards |

Split `tests/test_guard.py` the same way: `test_shell_scan.py` (direct unit tests of the tokenizer), `test_push_policy.py`, `test_config_write.py`, and `test_guard.py` (end-to-end through the hook).

Fold in the high-risk reviewer's maintainability recommendation from the CH-03 review, if it asks for a structural simplification. Any behaviour change it implies needs owner approval first.

Don't: change any decision, message or exit code; add dependencies; change `harness_config.py` beyond imports.
