# CH-16: Board reads live worktrees

## Status

in progress (2026-11-23), Milestone B

## Depends on

CH-15

## Scope

The owner's 2026-11-23 requirement, written out in full in `docs/STATUS.md` under Milestone B: a ticket being built shows as In progress or In review on the board before it is merged.

- **Finding live worktrees:** read `git worktree list --porcelain` from the main checkout. A worktree on `feature/<id-lowercase>` (the branch pattern from the Harness section; default `feature/*`) maps to a known ticket ID, ignoring case. Worktrees that match no ticket are ignored.
- **Shown state:** the most advanced of these three:
  - main's state;
  - In progress (a live worktree exists);
  - the state in the worktree's own tracker row or ticket file, committed or not.

  Order: Planned < In progress < Fixing < In review.
- **Caps:**
  - Unmerged work shows at most In review.
  - Owner check, Done, Blocked and Deferred on main are never moved.
- **Card:** shows the branch the state came from (e.g. "from feature/ch-14").
- **`--check`:** still compares only main's row with main's file, so a worktree being ahead is not a mismatch.
- **When git fails:**
  - The board still builds when git is missing, the folder isn't a repo, or there are no worktrees.
  - Prunable or missing worktrees are skipped.
  - Every git call has a timeout.
- **Output location:** the board is always written into the main checkout's `boardPath`, even when run from a worktree (resolved with `git rev-parse --git-common-dir`).

Don't: change any file in a worktree; run git commands that write.

## Done criteria

- Real-git tests in temp repos:
  - planned on main plus a worktree means In progress;
  - a worktree whose row says In review (committed, and uncommitted) means In review;
  - a worktree row saying Done shows only In review;
  - Done or Blocked on main does not move;
  - a non-ticket branch is ignored;
  - a prunable worktree is skipped;
  - no git means the board still builds;
  - running from a worktree writes to the main checkout;
  - `--check` ignores worktrees.
- A mutation check: dropping the cap fails a test.
- Full suite and static check pass. Review rounds: at most 2.
