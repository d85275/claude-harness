# CH-32: The board's Done column is collapsed by default

## Status

done (2026-11-25): owner decision, after a project with almost 200 Done tickets switched over

## Depends on

none (runs after CH-31; tickets run one at a time)

## Scope

A project with many finished tickets gets a very long Done column, which pushes the open work out of view.

- The Done column starts collapsed: a narrow column with its title and count (the count still follows the filters). One click or key press (a real button with `aria-expanded`) opens it; another closes it.
- The choice is remembered per board in the browser (`localStorage`, every read and write in try/catch; without storage the board works and starts collapsed).
- Search and the filters still cover Done tickets. When a search or filter matches Done cards, the collapsed column shows the matching count and a hint to open it; opening a Done ticket by link (`#<ID>`) works and shows its issue view.
- Other columns are unchanged. Light and dark themes, phone width and the board's other behaviour stay as they are. The board stays one offline HTML file with no outside resources.
- Regenerate `docs/examples/board.html` (and the README images only if they change visibly; say so).

Don't: drop Done tickets from the HTML; change `--check`, `--json` or the parser.

## Done criteria

- Tests on the rendered HTML: the Done column has the collapse button and starts collapsed; other columns do not; the count element is still present; Done cards are still in the page.
- A headless browser check (as in earlier board tickets, if Chrome is available; otherwise say so): collapsed at load, opens on click, remembered after reload, a search for a Done ticket shows the hint, `#<ID>` of a Done ticket opens it, no console errors.
- Full suite and static check pass. Review rounds: at most 2.
