# CH-29: Plugin ticket commands leave projects that have not switched over alone

## Status

in review (2026-11-23), owner request before tagging 1.0

## Depends on

CH-20, CH-25

## Scope

In 1.0 the plugin's `/start-ticket` and `/review` run `dev-harness-board set-state`, and `/close-ticket` and the board rebuild the board at `tickets.boardPath`. Projects that run their own ticket system (not switched over; adoption is planned after 1.0) get their tracker edited with the plugin's states, and a project whose own board lives at the default `docs/tickets/board.html` gets it overwritten.

Rule: the plugin's ticket features act only in a project that has opted in, meaning a project `harness.json` (any of the files the config loader reads, not the built-in defaults) has a `tickets` section. `/ticket-init` writes one; a future switch-over writes one.

- New `dev-harness-board status` (or `enabled`): prints whether the project uses the plugin's ticket system and why, exit 0 yes, exit 1 no. Read-only.
- In a project that has not opted in:
  - `set-state`, `archive`, `install-hooks` refuse with one clear line ("this project has not switched to the plugin's ticket system; nothing changed") and exit 1;
  - the plain render writes nothing unless `--out` is given; `--check`, `--json` and `twin` stay read-only and still work;
  - the `hook` mode does nothing (exit 0).
- Commands: `/start-ticket`, `/review`, `/close-ticket` and the implementer agents run their state and board steps only when `dev-harness-board status` says yes, and otherwise skip them silently and follow the project's own Harness section. Say this in each command text in one sentence.
- This repo opts in: add `.claude/harness.json` with a `tickets` section (the current defaults made explicit), so its own flow keeps working.
- README / docs: one sentence each where the board and these commands are described; CHANGELOG 1.0.0 entry updated.

Don't: change what happens in a project that has opted in; change the guards.

## Done criteria

- Tests: a project without a `tickets` section: `set-state`, `archive`, `install-hooks` refuse and change no byte; render without `--out` writes nothing; `--check`/`--json` work; `hook` is a no-op. With a `tickets` section (including one in a parent folder's config, if the loader reads it): everything works as before.
- This repo: `--check --root .` exit 0, `status` says yes. The sample project: `status` says yes.
- Full suite passes. Review rounds: at most 2.
