# CH-01: One `harness.json` schema and a shared config loader

## Status

done (2026-11-22), integrated as c2efe7d after 3 review rounds and an owner decision (configs merge, never weaker)

## Depends on

none

## Scope

Today `.claude/harness.json` only holds guard rules, and `guard.py` silently falls back to `{}` when the file is malformed, so a typo quietly switches off the project's own rules. Version 1.0 adds push policy, presets and ticket settings to the same file.

- Add a shared loader `hooks/scripts/harness_config.py` that `guard.py` (and later the board and `/ticket-init`) use. It must work under `python3 -I`, which leaves the script's folder off `sys.path`, so callers add it explicitly.
- Schema (all keys optional, documented defaults):
  - `version`: `1`
  - existing guard keys: `protectedPaths`, `protectedConfigs`, `askCommands`, `checkWeakening`, `weakeningMarkers`, `notify`
  - `pushPolicy`: `"ask"` (default) | `"deny"` | `"allow"` (enforced in CH-03)
  - `presets`: list of opt-in rule sets (filled in CH-06)
  - `highRiskReviewerModel`: `"opus"` (default) | `"fable"` (used in CH-02)
  - `tickets`: `dirs`, `featureGlobs`, `idPrefixes` (prefix -> `{platform, kind}`), `twinPlatforms` (list or `null`), `archive` (bool), `trackerPath`, `integrationBranch`, `boardPath`
- A malformed file or an unknown key is reported (stderr message from the hook) instead of ignored. A missing file still means "all defaults".

Don't: change guard behaviour beyond loading and reporting config; add third-party dependencies.

## Done criteria

- `templates/harness.json` shows every key with a short comment-free example; README lists each key with its default.
- Tests: missing file -> defaults; malformed JSON -> reported, guard still enforces built-in rules; unknown key -> reported; each documented default is pinned.
- `python3 -m unittest discover -s tests` passes.

## Allowed files

`hooks/scripts/harness_config.py`, `hooks/scripts/guard.py`, `templates/harness.json`, `tests/`, `README.md`

## Review level

standard + silent-failure-hunter (config errors must not be swallowed)

## Findings

Review round 1 (all fixed in the amended commit):

1. Critical: config warnings went to stderr on exit 0, which neither the user nor Claude sees. Fixed: `guard.py` keeps the text and emits exactly one JSON object via `emit()`: `systemMessage` (user) plus `hookSpecificOutput.additionalContext` (model) on allow; the same object carries `permissionDecision` and the warning appended to the reason on ask; the warning is appended to the stderr message on block; notify gets `systemMessage` only. stderr is still written. Valid or missing config: stdout unchanged. The combination of `systemMessage` with `hookSpecificOutput` is not shown in the docs; README says to verify with `claude --debug`.
2. Important: deeply nested JSON raised `RecursionError` and crashed the hook (non-blocking, so the tool call went ahead). Fixed: `load_config` never raises; any unexpected exception is reported and defaults are used. Test: a nested file still blocks a `.pem` read and warns.
3. Important: an invalid `weakeningMarkers` regex made `re.findall` raise. Fixed: patterns are checked with `re.compile` at load (bad ones dropped and named), and `added_weakening` skips a bad pattern. Test: `["("]` plus an edit adding `# noqa` still asks.
4. Important: one bad value dropped a whole protection list. Fixed: a bare string becomes a one-item list; bad elements are dropped and named; messages say which protections are NOT active. Non-protective keys keep default plus report.
5. Important: config was read only from `cwd`, so a `cd` into a subfolder switched project rules off (a bypass). Fixed: nearest `.claude/harness.json` walking up from `cwd`, then `$CLAUDE_PROJECT_DIR`; `protectedPaths` and `protectedConfigs` also match relative to that root. This goes slightly past "no guard behaviour change" and was approved as a bypass fix. Correction (coordinator): the walk stops at the repo root (first folder with `.git`, a directory or a worktree file, checked itself; else `$CLAUDE_PROJECT_DIR` if `cwd` is inside it; else `cwd` only) and never reads above it, so `~/.claude/harness.json` (Claude Code's own user folder) cannot leak into unrelated projects.

Review round 2 (all fixed in the amended commit):

6. Critical: `os.path.isfile` made an existing but unreachable `harness.json` (dangling symlink, symlink loop, directory, unreadable `.claude`) read as "no config". Fixed: presence is an `os.lstat` check where only `FileNotFoundError` and `NotADirectoryError` mean absent; anything else counts as present, so `open()` fails and the error is reported with "project protections NOT active". Tests for each case, plus built-in rules still blocking a `.pem` read (the chmod case is skipped as root).
7. Important: lookup order changed. `$CLAUDE_PROJECT_DIR/.claude/harness.json` is authoritative when present, with a notice naming any nested file it overrides; otherwise walk up to the repo root; if nothing is found and `CLAUDE_PROJECT_DIR` is unset, a config above the repo root (e.g. the parent of a submodule) is only warned about, never loaded. Deliberate consequence: inside a worktree, the main checkout's config applies, so an agent cannot weaken rules by editing its worktree copy.
8. Minor: `CONFIG_WARNING` is set before the stderr write, which is wrapped in `try/except OSError`.
9. Minor: `main` catches `Exception` (not `SystemExit`), emits a `systemMessage` "hook crashed ... this call was not checked", exits 0, and falls back to a guarded stderr write. Test: `"cwd": 5` with `cat x`.
10. Minor: the loader-level recursion test patches `json.load` to raise `RecursionError`; the real deep-nesting integration test stays.
11. Minor: on block the warning was on stderr twice; `block()` no longer repeats it (it is already on stderr from `load_config`).

Round 3 and owner decision (2026-11-22: configs merge and are never weaker):

12. Important: "`CLAUDE_PROJECT_DIR` wins" dropped a nested config's rules that the old code enforced (e.g. a nested `protectedPaths` or `askCommands`). Fixed by merging. Sources: the root config plus the nearest file from `cwd` to the `.git` boundary (every file up to the boundary when `CLAUDE_PROJECT_DIR` is unset or has no config). Each file loads independently, so a broken one is reported and the others still apply. Merge: union (deduplicated) of `protectedPaths`, `protectedConfigs`, `askCommands`, `weakeningMarkers`, `presets`; strictest `pushPolicy`; `checkWeakening` true if any is true; the root wins for the remaining keys, falling back to nested. Globs also match relative to every loaded file's project folder, plus the `cwd` and root matching from before. No notice for identical copies (equal after parsing); one notice naming the files when they differ; the old "ignoring nested" notice is gone. A stricter worktree config therefore applies immediately, a weaker one changes nothing.
13. Minor: the stderr write in `guard.load_config` now catches `Exception` (stderr may be `None` or closed); the crash `systemMessage` includes the config warning when one is set.
