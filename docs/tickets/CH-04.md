# CH-04: Ask before `git stash` with other worktrees, and before changing `core.hooksPath`

## Status

in review

## Depends on

CH-08 (rules go in `bash_rules.py`)

## Scope

- **Stash:** the stash is shared by every worktree of a repo, so a stash made by one agent can be popped by another. When the repo has more than one worktree, ask before a stash command that changes the stash or the working tree.
- **Hooks path:** `core.hooksPath` replaces `.git/hooks`, which silently disables hooks such as Git LFS's pre-push. Ask before setting or unsetting it.

### Must catch (each one a corpus row)

Stash, with two or more worktrees:
- `git stash`
- `git stash push`, `push -u`, `push -m "msg"`, `save "msg"`
- `git stash pop`, `apply`, `drop`, `clear`
- `git -C <dir> stash pop`
- chained forms: `git add -A && git stash`, `make; git stash pop`
- inside `sh -c '…'`

Hooks path:
- `git config core.hooksPath x`, also with `--local`, `--global`, `--worktree` or `--system`
- `git config --unset core.hooksPath` and `--unset-all`
- the key in any letter case (`core.hookspath`; git keys ignore case)
- `git -c core.hooksPath=x <anything>`

### Must pass

- `git stash list` and `git stash show`, with any number of worktrees
- every stash command when the repo has a single worktree
- `git config --get core.hooksPath`, plain `git config core.hooksPath` (a read), `git config --list`

### Known gaps (document in README, do not chase)

- git aliases
- commands built from variables
- scripts
- editing `.git/config` directly

### How

- **Where:** rules go in `bash_rules.py`. Reuse `ShellCheck`'s segments and `Budget`, with no new `shlex` pass. A new regex reads `full` and honours the data-heredoc spans (the CH-03 structural rule).
- **Worktree count:** run `git worktree list --porcelain` only when a stash command is detected, with a 2 s timeout. If the count can't be determined, ask with "could not count worktrees".

Don't: guard other `git config` keys.

## Done criteria

- Every "Must catch" and "Must pass" item is a row in `tests/data/guard_corpus.txt`, or a test with a temporary repo where worktrees matter. Rows cover the one- and two-worktree cases and the git-failure case.
- README hooks table and known gaps updated.
- Full suite passes.
- Review rounds: at most 2. Findings outside the catch list become documented gaps or a follow-up ticket, not another round.
