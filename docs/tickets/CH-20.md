# CH-20: Start, review and close keep ticket state; release check in `/sync`

## Status

done (2026-11-23), integrated as ce55063 after two review rounds (accept with minor notes)

## Depends on

CH-16 (for the board rebuild and the worktree states), CH-18 (template wording)

## Scope

The commands move a ticket through its states, so the tracker and board stay true without manual edits.

- **`/start-ticket`:**
  - Before launching the implementer, it sets the row and the ticket's Status line to In progress, in the worktree after it's created, so main is untouched until close. The board shows it through CH-16.
  - It refuses a ticket whose state is Done, Blocked or Deferred unless the owner says so.
- **`/review`:**
  - When the review starts, the worktree's row and Status line are set to In review.
  - On CHANGES REQUIRED, they are set to Fixing.
  - The implementer amends its one commit with that change. Say this in the command text.
- **`/close-ticket` additions:**
  - On main after the cherry-pick, the row is set to Done with the commit SHA, in the docs close commit.
  - **Twin check** (when `twinPlatforms` is on): report whether the twin ticket is open; never close it.
  - **Archive move** (when `archive` is on): the row and file move to the archive tracker and folder, and links are fixed.
  - **Board rebuild:** run `dev-harness-board` and then `--check`. A mismatch stops the close.
- **`/sync`:**
  - It runs `dev-harness-board --check` and lists its problems.
  - **Release check:** "before a release candidate, list every open ticket: Planned ones aimed at the next release, and every Owner check".
  - It stays read-only.

Don't: let any command push; change the one-commit-per-ticket rule; edit a ticket's Findings or Evidence on the owner's behalf.

## Done criteria

- The command texts state each step exactly, with the files they touch.
- A scripted walk-through on a fixture project (real git, temp folder) goes through each step: start, review, fixing, review, close. After each step it checks the tracker row, the Status line and the board column, and `--check` is clean at the end.
- The archive move and the twin check are each tested on a fixture.
- Full suite and static check pass. Review rounds: at most 2.
