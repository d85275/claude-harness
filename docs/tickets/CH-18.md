# CH-18: `/ticket-init` for a new project

## Status

planned (2026-11-23), Milestone B

## Depends on

CH-17

## Scope

A new command `commands/ticket-init.md` that sets up the ticket system in a project that has none. It gets one command-line helper (`dev-harness-board init`) that does the file writing, so the steps can be tested.

- **Asks first** (the command, not the helper): the ID prefix, the integration branch, archive on or off, twin platforms (off by default), and whether to install the hooks.
- **Writes only files that don't exist yet:**
  - `docs/tickets/TEMPLATE.md` (from this repo's template, made general);
  - `docs/tickets/tracker.md` with the States line and an empty table;
  - `docs/STATUS.md` skeleton;
  - the `tickets` section of `harness.json` (merged into an existing file without dropping keys; JSON stays valid);
  - the Harness section in `CLAUDE.md` (appended if missing; never edits an existing one; prints what it would add instead).
- **Harness section template** (`templates/CLAUDE-harness-section.md`) gains:
  - a short "how tickets work" part: states, tracker as the source of truth, the board, `/start-ticket`, `/review`, `/close-ticket`;
  - the owner rule: ticket-flow changes (states, start/review/close steps, board, git hooks, guards) go to the dev-harness plugin as a request, not into the project's own scripts.
- **Board and hooks:** builds the board once; installs the hooks only if the owner said yes (CH-17 installer).
- **`--dry-run`:** lists every file it would write or change, and writes nothing.
- **Re-running** on a project that already has the files changes nothing and says so (idempotent).

Don't: overwrite or reformat any existing file (adoption of existing trackers is CH-19); commit anything (the owner or coordinator commits).

## Done criteria

- Tests in temp folders:
  - a fresh repo gets every file, and `--check` passes on it;
  - a second run changes nothing (byte-identical);
  - an existing `harness.json` keeps its other keys;
  - an existing `CLAUDE.md` Harness section is not touched;
  - `--dry-run` writes nothing;
  - no hooks are installed unless asked.
- Full suite and static check pass. Review rounds: at most 2.

## Allowed files

`commands/ticket-init.md`, `board/`, `bin/dev-harness-board`, `templates/`, `tests/`, `README.md`
