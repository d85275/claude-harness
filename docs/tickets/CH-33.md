# CH-33: Fewer prompts during ticket work

## Status

done (2026-11-25): owner request; prompts break continuous ticket work

## Depends on

CH-31 (same guard files; runs after it)

## Scope

In a real project, one day of ticket work produced about a dozen guard prompts and many Claude Code approval prompts. Besides the wildcard prompts fixed by CH-31, two causes:

- **Deploy rule reads heredoc text.** `ALWAYS_ASK_COMMANDS` and `askCommands` (`hooks/scripts/bash_rules.py`) are matched against the whole command, including the body of a proven data heredoc (`cat > docs/x.md <<'EOF' ... gcloud ... update ... EOF`). Writing a ticket or checklist that mentions a deploy command asks. Fix: match them against the text outside data heredoc bodies, as the credential, push and config rules already do (CH-10), with the same fail-closed cases (when `data_text_unsafe`, the whole text counts). Code heredocs (`python3 - <<EOF`, `sh <<EOF`) still count.
- **Agents edit files through the shell.** Implementers, reviewers' probes and the coordinator command texts write files with `python3 - <<EOF`, `cat > file <<EOF`, `printf >>` and chained `cd X && ...`, which ask in Claude Code and trip guard rules. Fix in the texts: write and edit files with the Edit and Write tools; run one plain command per Bash call (no `cd` chains: pass `-C`/`--root` or use absolute paths); keep shell for running builds, tests, git and the board. Applies to `agents/implementer.md`, `agents/implementer-advanced.md`, the reviewer agents (probes in the scratchpad), and the commands that edit files.

Don't: drop any deploy pattern, or exempt code heredocs; change push, credential or protected-config rules (CH-31 owns the wildcard change).

## Done criteria

- Tests: a data heredoc writing text with `firebase deploy`, `gcloud ... update`, `terraform apply`, `kubectl delete` and an `askCommands` entry passes; the same commands run for real, in `python3 - <<EOF`/`sh <<EOF` bodies, after `;` on the heredoc line, and in an unsafe heredoc (the CH-12/CH-13 cases) still ask. The pass tests fail before the change. The guard corpus passes.
- The agent and command texts say how to edit files and run commands, in one short paragraph each; `tests/test_docs.py` (or a new test) checks the agent files carry it.
- `docs/guards.md` updated. Full suite and static check pass. Review rounds: at most 3.

## Allowed files

`hooks/scripts/bash_rules.py`, `agents/*.md`, `commands/*.md`, `tests/`, `docs/guards.md`, `docs/agents.md`

## Findings

- **Deploy rule.** `bash_rules.check` now matches `ALWAYS_ASK_COMMANDS` and `askCommands` with `DataText.search` (the same object, spans and `DATA_TEXT_UNSAFE` cases the credential and device-reset rules use) instead of `re.search` on the raw command. No pattern was dropped or changed; push, credential and protected-config rules are untouched.
- **Stricter side effect (asks more).** `DataText.search` also reads the text with backslash-newlines joined, so `firebase \` + `deploy`, `gcloud run \` + `deploy demo` and `terraform \` + `apply` now ask; on the base commit they passed (shown by the base run below). A raw-text hit that exists only because of a backslash-newline glued to a word (`x\` + `gcloud deploy`, which bash reads as `xgcloud`) is no longer counted when a data heredoc body is present; bash would not run it as that word.
- **Unquoted heredoc with backticks asks, correctly.** A checklist written with `<<EOF` (unquoted) that puts commands in backticks runs them, so it is not data and still asks; with `<<'EOF'` it passes. A test pins both.
- **Texts.** Each agent and command file carries one **Files and shell** paragraph. Implementers: Edit/Write only, one plain command per Bash call, absolute paths for `git -C` and `--root`, no `cd` chains, clean task instead of wildcard or variable `rm`, scratch files in the scratchpad, stop and report a command that asks. Reviewers keep their tools (no Write): one plain command per call, absolute paths, probes by rerunning tests or one `python3 -c`, a probe that needs a file goes under "not verified". `/start-ticket` and `/review` pass the rules into implementer and reviewer briefs (and into findings sent back). Relative `--root .worktrees/<id>` / `--root <your worktree>` became absolute paths; `/ticket-init` writes its `--check` output to a scratchpad path instead of `$(mktemp)`.
- **Decision for the owner.** The ticket says reviewer probes go in the scratchpad, but the three reviewers have no Write tool. This change does not widen their tools; adding `Write` (scratchpad only, by instruction) to `reviewer`, `high-risk-reviewer` and `silent-failure-hunter` is the owner's call. **Owner decision (2026-11-26): reviewers keep no Write tool** (see round 1, point 2).
- **High-risk review round 1 (of afcdcc0): changes required, wording only; the guard part held (52 command shapes, every real deploy asks). No code change in the amend.**
  1. *Commands that read the current folder.* "Use absolute paths" did not cover a test runner or build run without `cd`: the subagent shell is back in the main checkout after every call, so it would test main's code and record that as Evidence. The implementer, reviewer, `/start-ticket` and `/review` paragraphs now say: such a command takes the tool's folder option (`python3 -m unittest discover -s <abs>/tests`, `make -C <abs>`, `npm --prefix <abs>`, `go -C <abs>`, `./gradlew -p <abs>`, `git -C <abs>`), and without one the agent stops and reports. The two brief bullets carry it too; `docs/agents.md` says why.
  2. *Reviewer probes.* "No ... other writes through the shell" blocked the check that new tests fail on the base tree. Reviewers may now run plain commands that write their own output into the scratchpad (test results, `git archive -o`, `tar -x -f ... -C`, `cp` into the scratchpad); hand-written files (`printf >> file`, `cat > file <<EOF`) stay banned, and so do heredoc scripts. Their opening "Bash is only for ..." lines now name these scratchpad copies, so the two texts agree. Same in the `/review` brief bullet and `docs/agents.md`.
  3. *guards.md.* The deploy rule's Known gaps now say a file written by a data heredoc and then run without being named (glob, `make` reading a Makefile, `npm test` reading package.json, a multi-line group piped to a shell) is not seen.
  - `FilesAndShellTextTest` pins the folder-option sentence (agents, `/start-ticket`, `/review`, both brief bullets) and the reviewer scratchpad wording. Its paragraph length cap (added by this ticket, not an existing threshold) went from 1000 to 1600 characters for the extra sentences.
