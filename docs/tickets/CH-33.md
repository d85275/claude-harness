# CH-33: Fewer prompts during ticket work

## Status

planned (2026-11-25): owner request; prompts break continuous ticket work

## Depends on

CH-31 (same guard files; runs after it)

## Scope

In a real project, one day of ticket work produced about a dozen guard prompts and many Claude Code approval prompts. Besides the wildcard prompts fixed by CH-31, two causes:

- **Deploy rule reads heredoc text.** `ALWAYS_ASK_COMMANDS` and `askCommands` (`hooks/scripts/bash_rules.py`) are matched against the whole command, including the body of a proven data heredoc (`cat > docs/x.md <<'EOF' ... gcloud ... update ... EOF`). Writing a ticket or checklist that mentions a deploy command asks. Fix: match them against the text outside data heredoc bodies, as the credential, push and config rules already do (CH-10), with the same fail-closed cases (when `data_text_unsafe`, the whole text counts). Code heredocs (`python3 - <<EOF`, `sh <<EOF`) still count.
- **Agents edit files through the shell.** Implementers, reviewers' probes and the coordinator command texts write files with `python3 - <<EOF`, `cat > file <<EOF`, `printf >>` and chained `cd X && ...`, which ask in Claude Code and trip guard rules. Fix in the texts: write and edit files with the Edit and Write tools; run one plain command per Bash call (no `cd` chains: pass `-C`/`--root` or use absolute paths); keep shell for running builds, tests, git and the board. Applies to `agents/implementer.md`, `agents/implementer-advanced.md`, the reviewer agents (probes in the scratchpad), and the commands that edit files.

Don't: drop any deploy pattern, or exempt code heredocs; change push, credential or protected-config rules (CH-31 owns the wildcard change).

## Done criteria

- Tests: a data heredoc writing text with `firebase deploy`, `gcloud ... update`, `terraform apply`, `kubectl delete` and an `askCommands` entry passes; the same commands run for real, in `python3 - <<EOF`/`sh <<EOF` bodies, after `;` on the heredoc line, and in an unsafe heredoc (the CH-12/CH-13 cases) still ask. The pass tests fail before the change. The guard corpus passes.
- The agent and command texts say how to edit files and run commands, in one short paragraph each; `tests/test_docs.py` (or a new test) checks the agent files carry it.
- `docs/guards.md` updated. Full suite and static check pass. Review rounds: at most 3.
