# CH-19: `/ticket-init` adopts existing trackers, with a dry-run migration report

## Status

in progress (2026-11-23), Milestone B

## Depends on

CH-18

## Scope

The owner's projects already have real tickets, trackers, and in one case their own board script and hooks. `/ticket-init` must adopt them without rewriting any old ticket (owner, 2026-11-23; see `docs/STATUS.md` Milestone B).

- **Detect:** when a tracker or ticket folder already exists, `/ticket-init` goes into adopt mode. It never writes TEMPLATE, tracker or ticket files.
- **`/ticket-init --check` (dry run) writes nothing and reports:**
  - ticket counts per state, next to the counts on the project's current board if one exists (read from its HTML or its tracker; best effort, and says when it can't tell);
  - unknown state names, with a suggested `stateAliases` entry;
  - files without rows and rows without files;
  - broken links;
  - ID prefixes seen, with a suggested `idPrefixes`;
  - archive and feature folders seen, with suggested `archive`, `archiveTracker`, `archiveDirs` and `featureGlobs`;
  - extra tracker columns, with a suggested `extraColumns`;
  - an existing board script, git hooks or `core.hooksPath`, which the switch would replace.
- **Suggested settings:** the report ends with a complete `tickets` block for `harness.json`, built from what it found. Differences are mapped through settings, never by editing tickets.
- **Switch (not dry run):** writes only:
  - the `tickets` settings;
  - the board;
  - the hooks, if the owner agrees: the old `core.hooksPath` is reported, not overwritten (CH-17 refuses); the coordinator removes the old board hooks in the same commit;
  - the Harness section additions (printed if one exists).
  It prints the list of files, so the switch is one revertible commit.
- **Match before switching:** the command reports whether the plugin's board has the same tickets in the same columns as the old board. A difference is listed per ticket, and the switch is refused until the owner fixes the settings or accepts each difference.

Don't: rename, move or reformat any existing ticket, tracker or archive file; delete the old board script or hooks (the project's own switch-over ticket does that).

## Done criteria

- Fixture projects (made-up tickets) shaped like the two real layouts:
  - **project A:** open tracker plus an archive, feature folders, twin tickets, its own board script and a `.githooks/` with LFS chaining;
  - **project B:** all files in one folder, several ID prefixes, a separate integration branch, extra columns, states named differently.
- For each fixture: `--check` writes nothing and finds every difference planted in it; applying the suggested settings makes `dev-harness-board --check` pass with no ticket file changed (checked by hashing every file before and after).
- The match check lists a planted column difference and refuses the switch.
- Full suite and static check pass. Review rounds: at most 2.

## Allowed files

`commands/ticket-init.md`, `board/`, `bin/dev-harness-board`, `hooks/scripts/harness_config.py` (only if a new setting is needed), `tests/`, `README.md`

## Review level

standard + silent-failure-hunter (a dry run that misses a difference is a silent failure)
